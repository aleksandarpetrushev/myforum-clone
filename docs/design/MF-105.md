# MF-105 Admins find their organization's drafts

Status: decided, ready for planning
Author: Aleksandar Petrushev
Date: 2026-11-12

## Problem

An organization admin who saves an event as a draft can only get back to it with the link, and cannot publish it from the app: the API accepts `PATCH /api/events/:id` with `status: "published"` (MF-101), but Angular has no call for it. The ticket's "so that I can finish and publish them" is impossible today without `curl`.

## Requirements

From the ticket and the PO on 2026-11-12:

- An organization's admins can find every draft of their organization's events without the link.
- A draft is clearly marked as a draft wherever it appears.
- Nobody else ever sees a draft.
- Discovery does not fill up with drafts for admins who browse as participants.
- An admin can publish a draft from its page (PO: in scope). Editing a draft's fields is out of scope; admins delete and recreate for now.

## How the code behaves today

| Area | Today |
|---|---|
| Who can see a draft | `EventPolicy`: only admins of the organizing organization, including by direct link |
| Discovery | `GET /api/events` lists `policy_scope(Event).published`, so drafts never appear, for anyone. The first page is cached per user (ADR 0005) |
| Publishing | `PATCH /api/events/:id` with `status` through `Events::Update`: row lock, allowed-organization validation, `EventUpdated` and `EventPublished` outbox rows, cache invalidation |
| Past start | Nothing stops publishing a draft whose start time has passed |
| Event page | No draft label; shows Register on a draft, which answers 404 |
| Angular | No drafts list, no publish call, no toast component; messages are shown inline |

## Decisions

| # | Decision | Choice | The thing that goes wrong otherwise |
|---|---|---|---|
| D1 | Where drafts appear | Their own list, "My drafts", reachable by admins only. Not in discovery | Admins browsing as participants see unpublished events mixed in; discovery is for finding events to attend. Cost: searching discovery never finds a draft |
| D2 | List API | New `GET /api/me/drafts`: drafts of organizations the user administers, soonest first, each with its organization's name | A `?drafts=true` parameter on `GET /api/events` would have to be kept out of its per-user first-page cache by hand; a miss would cache drafts with published events |
| D3 | Marking | "Not published" on the draft's page and on every row of My drafts | An admin mistakes a draft for a live event |
| D4 | Participant actions on a draft | Register and Join waitlist stay visible but disabled, with visible text below: "You can register once the event is published." No tooltip | Buttons vanishing without explanation; a tooltip on a disabled button never shows, because disabled buttons get no hover or keyboard focus |
| D5 | Publish | A Publish button on the draft's page for the organization's admins, calling `POST /api/events/:id/publish`. The endpoint runs `Events::Update` with `status: "published"`: one transaction under the row lock, which validates and publishes together | A separate "can publish?" check that says yes at page load and is stale by the click |
| D6 | Refusing to publish | 422 with the reasons, shown inline: the start time has passed; a restricted event with no allowed organizations; a status the state machine refuses (not a draft) | Publishing an event nobody can attend, or a restricted event nobody can see |
| D7 | Past start | Validated on the `Event` model whenever a draft becomes published, so `POST /publish`, `PATCH` and create with `status: "published"` all refuse it | A rule only the new button checks, bypassed by the existing `PATCH` |
| D8 | After publishing | The page reloads the event and shows inline: "Published. Participants will see it in discovery within a minute." | An admin wondering why discovery does not show it yet (the list cache lasts one minute) |

## Design

### Rails

- `Event`: `validate :starts_in_the_future_when_published`, applied when `status` changes from `draft` to `published`.
- `GET /api/me/drafts` (`Api::Me::DraftsController#index`): `Event.where(status: "draft", organization_id: <orgs the user administers>)`, `in_start_order`, `as_list_json`. Goes through `policy_scope(Event)` as well, so the policy stays the single gate.
- `POST /api/events/:id/publish` (`Api::EventsController#publish`): `policy_scope(Event).find`, `authorize event, :update?`, then `Events::Update.new(event:, attributes: { "status" => "published" }).call`. Both a refused state-machine transition (already published) and failed validations answer through the existing handler: 422 `validation_failed` with the reasons.

### Angular

- Route `/drafts`, "My drafts" in the navigation for users with admin organizations (`AdminOrganizationsService.canCreate()`).
- `ForumApi`: `drafts()`, `publishEvent(id)`.
- `DraftsComponent`: each draft with title (linked), start time, organization name and "Not published"; empty state "No drafts".
- `EventDetailComponent`: when `status === 'draft'`, "Not published" label; Register and Join waitlist disabled with the explanation below; Publish button for the organization's admins; inline success or the server's reasons.
