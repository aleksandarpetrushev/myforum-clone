# MF-202 Waitlist for full events

Status: decided, ready for planning
Author: Aleksandar Petrushev
Date: 2026-11-10

## Problem

A full event is a dead end: `POST /api/registrations` answers 409 `event_full`, and MF-201 stopped recommending full events for that reason (its D12). Participants want to queue for a seat and get it if one frees up.

## Requirements

From the ticket and the PO on 2026-11-10:

- Joining a waitlist is idempotent, and the user can see their position.
- When a seat frees up, the first person in line is offered it and notified.
- Promotion never pushes an event past its capacity, even when two cancellations land at the same moment.
- The organizer sees the waitlist count.
- A freed seat is **offered**, not given: the person confirms it within min(24 hours, half the time until the event starts), or it passes to the next person.
- **No offers in the last hour before the start.** The waitlist closes then; a seat still free is open for normal registration.
- An offered seat is held: nobody else can register into it while the offer runs.
- Notifications stay in-app. Only the person offered a seat, and a person whose offer lapsed, are notified.

## How the code behaves today

| Area | Today |
|---|---|
| States | `Registration`: `confirmed`, `cancelled`, `failed`. One row per user and event (unique index); a cancelled row is reconfirmed with `lifecycle_version + 1` |
| Seats | `events.reserved_spots`, guarded by the row lock in `Events::Register` and `Registrations::Cancel` and by the check `reserved_spots <= capacity` |
| Freeing seats | Participant cancel (`Registrations::Cancel`); raising `capacity` (`Events::Update`); organizer cancel (`CancelEventRegistrationsJob`, confirmed rows only) |
| Revisions | Every change to the event row bumps `events.revision` (MF-106) |
| `cancelled_by` | `participant` or `organizer` (check constraint) |
| Notifications | Outbox-driven. `SendNotificationJob::COPY` maps an event type to a kind; a kind without a preference column is always sent |
| Go | Every outbox row is delivered. A type missing from the contract's `event_type` enum is answered `unsupported_contract` and the row is `deferred` (MF-203) |
| Recommendations | `Recommendations::ForUser` drops full events (MF-201 D12) and events the user is registered for |
| My registrations | Upcoming and Past by event time (MF-103); labels for cancelled and failed rows |

## Decisions

| # | Decision | Choice | The thing that goes wrong otherwise |
|---|---|---|---|
| D1 | Where waitlist entries live | New `Registration` states `waitlisted` and `offered`, plus `waitlisted_at`, `offered_at`, `offer_expires_at` | A separate table that later has to be merged with, or migrated out of, a production-sized `registrations` table |
| D2 | Seats | `reserved_spots` counts `confirmed` and `offered` rows | An offered seat taken by a direct registration while the offer runs; overselling past the check constraint |
| D3 | When to offer | In the same transaction that frees seats, under the event row lock: participant cancel, a declined or expired offer, a capacity increase. Offer up to the number of free seats at once, oldest `waitlisted_at` first, as one batch | Two seats freed together offering the same person twice; a seat sitting free between the cancel and a later promotion step |
| D4 | Offer length | `offer_expires_at = now + min(24 h, (starts_at - now) / 2)` | An offer outliving the event, or a seat given to someone who no longer wants it |
| D5 | Last hour | No offers and no new waitlist joins when `starts_at - now <= 1 hour`. Free seats stay open for normal registration. Running offers run to their own expiry | Offers shrinking to minutes and a seat going unused while the line burns through |
| D6 | Expiry | `ExpireWaitlistOfferJob`, scheduled at `offer_expires_at` with the registration's id and `lifecycle_version`, so a stale job does nothing. Safety net: `bin/rails waitlist:expire_overdue` and `Metrics.overdue_waitlist_offers` | A lost scheduled job holding a seat forever |
| D7 | Expired offer | `offered` → `cancelled`, `cancelled_by: "offer_expired"`; the person leaves the line and is notified; the seat goes to the next person (D3) | The same person re-offered forever, or never told they missed it |
| D8 | Position | Computed when read: waitlisted rows of the event that joined earlier (`waitlisted_at`, then `id`), plus one. Index on `(event_id, status, waitlisted_at, id)` | A stored position rewritten for everyone behind a leaver: thousands of updates per departure, overlapping recompute jobs, and stale numbers |
| D9 | API | `POST /api/registrations/waitlist {event_id}` joins; `POST /api/registrations/accept_offer {event_id}` confirms; the existing `POST /api/registrations/cancel` leaves the line or declines an offer | Overloading `POST /api/registrations` so a client cannot tell "registered" from "queued" |
| D10 | Join rules | Already waitlisted or offered: 200 with the existing row (idempotent). Confirmed: 409 `duplicate_registration`. Seats free: 409 `seats_available` (register normally). Last hour: 422 `waitlist_closed`. Not published or not visible: 404 | A second click creating a second place in line; joining a line for a seat that is free |

Added to the contract's `event_type` enum: additive, no version bump. Go applies them as snapshot events. **Go deploys before Rails.** Accepting an offer writes `RegistrationCreated`. Joining and leaving write no outbox row. Declining writes `RegistrationCancelled` with `declined_offer: true`, which the notification job skips (changed in review: otherwise Go kept a stale seat count when nobody else was in line) | Offer rows answered `unsupported_contract` and deferred; Go's seat counts drifting |
| D12 | Notifications | `waitlist_offered` ("A seat opened for X: confirm by <time>") and `waitlist_offer_expired`. No preference columns, so they are always sent: they are actionable | An offer missed because its kind was muted |
| D13 | Organizer cancels the event | The cascade cancels `waitlisted` and `offered` rows too, with `cancelled_by: "organizer"`, and sends each person the existing `event_cancelled` notification | People waiting in line for an event that no longer exists |
| D14 | Organizer view | Event detail for the organizing organization's admins includes `waitlist_count` | — |
| D15 | Recommendations | Remove MF-201's full-event filter from `Recommendations::ForUser`; also drop events the user is waitlisted or offered for | Full events invisible though they can now be joined; recommending a line you are already in |
| D17 | The start moves (from review) | Free seats are offered to the line, and open offers that would end after min(24 h, half the time to the new start) are shortened and rescheduled | A seat left free in the closed last hour staying free after the start moved later; an offer outliving a start that moved earlier |
| D18 | Accepting (from review) | Only for a published event that has not started | Confirming a seat for an event cancelled before the cascade reached the offer |
| D16 | Frontend | Event page: "Join waitlist" when full, then "You are #N in line". ## Design

### Database

- `registrations`: add `waitlisted_at`, `offered_at`, `offer_expires_at` (all nullable); add `waitlisted` and `offered` to the status check; add `offer_expired` to the `cancelled_by` check. Index `(event_id, status, waitlisted_at, id)`.
- No change to `events`: the capacity check already guards `reserved_spots`.

### State machine

```
(none) / cancelled ──join──▶ waitlisted ──offer──▶ offered ──accept──▶ confirmed
                              │                     │
                              └──leave──▶ cancelled ◀──decline / expire──┘
confirmed ──cancel──▶ cancelled           (organizer cancel: any of the three ▶ cancelled)
```

Joining from a cancelled row bumps `lifecycle_version`, as reconfirming does today.

### Services

- `Waitlist::Join`, `Waitlist::AcceptOffer`: lock the event, then the registration.
- `Waitlist::OfferFreedSeats.call(event)`: called inside the transaction that holds the event lock. `free = capacity - reserved_spots`; unless in the last hour, take the first `free` waitlisted rows in order, mark them `offered` with one expiry, add them to `reserved_spots`, bump the revision once, write one `WaitlistOffered` row each, and schedule their expiry jobs after commit.
- `Registrations::Cancel`: a waitlisted row is cancelled without touching seats; an offered or confirmed row frees its seat and calls `OfferFreedSeats`.
- `Events::Update`: when `capacity` goes up, calls `OfferFreedSeats`.
- `ExpireWaitlistOfferJob` / `Waitlist::ExpireOverdue`: lock the event, expire the offer if still `offered` at the same `lifecycle_version` and past `offer_expires_at`, write `WaitlistOfferExpired`, call `OfferFreedSeats`.

### Contract and Go

`WaitlistOffered` and `WaitlistOfferExpired` join the `event_type` enum, pointing at `registrationChange`; one example each. Go's store applies them like the other snapshot events. Go is deployed first.

### Before merging PR B

1. `/code-review` and fixes.
2. End to end against Rails, Sidekiq and Go: fill an event, two people join, a registrant cancels, the first is offered; let an offer expire (short window via a near-start event) and see it pass on; organizer cancels with a line waiting.
3. PO acceptance.

### Risks

- **The state machine change touches every registration query.** B7 and B8 exist for that; the grep for `confirmed` in `app/` is the checklist.
- **Expiry relies on scheduled Sidekiq jobs.** B5's overdue task and metric are the fallback; the end-to-end run checks a real expiry.
- **Deploy order.** If PR B ships before PR A is deployed, offer rows are deferred, not lost (MF-203); run `bin/rails outbox:redeliver_deferred` after deploying Go.

## Out of scope

- Email or push notifications (notifications stay in-app).
- Sending waitlist joins to Go as an interest signal: the ranker does not use registrations as interest either.
- Telling people whose position moved.
