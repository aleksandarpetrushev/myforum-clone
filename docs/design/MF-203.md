# MF-203 A versioned contract between Rails and Go

Status: decided, ready for planning
Author: Aleksandar Petrushev
Date: 2026-11-09

## Problem

Rails and Go agree on the `POST /internal/events` payload only by convention. Nothing stops a Rails change from sending something Go cannot read, and Go would not notice: it never rejects a payload. An unknown `event_type` falls through its `switch` and gets 204. A missing field becomes a zero value, so a snapshot without `starts_at` is stored as year 1 and the event is silently never recommended. The risk is not that Go rejects what Rails sends, but that it accepts something broken and the result is silently wrong.

## Requirements

From the ticket:

- The payload for `POST /internal/events` is defined as a JSON Schema or OpenAPI document in the repo, with a version field.
- RSpec fails when Rails sends something off-schema, and `go test` fails when Go rejects a valid example.
- Go accepts both versions during a rollout, and the upgrade steps are written down.

## How the code behaves today

| Area | Today |
|---|---|
| Envelope | `Personalization::DeliverEvent` builds `{ idempotency_key, event_type, payload }` when the row is sent |
| Event types | `EventPublished`, `EventUpdated`, `EventCancelled`: `{ event }`. `RegistrationCreated`, `RegistrationCancelled`: `{ registration_id, user_id, event_id, user_location, event }`. `TopicFollowed`: `{ user_id, topic_id, user_location }`. `TopicUnfollowed`: `{ user_id, topic_id }` |
| Snapshot | `Event#snapshot`: `id`, `title`, `location`, `starts_at`, `status`, `reserved_spots`, `capacity`, `topic_ids`, `visibility`, `organization_id`, `allowed_organization_ids`, `revision` |
| Outbox | Payloads are stored when the row is written. After a deploy, rows written by the old code are still pending in the old shape |
| Failure | If Go answered non-2xx, `ProcessOutboxJob` would fail and stop rescheduling itself, stalling notifications and analytics too |
| Go ingest | Decodes into `map[string]any`; reads fields with zero-value fallbacks; ignores unknown fields and unknown event types |
| Tooling | No JSON Schema library on either side. Go depends only on `pgx` |

## Decisions

| # | Decision | Choice | Failure it protects against |
|---|---|---|---|
| D1 | Format | JSON Schema (draft 2020-12): one envelope schema, a `$defs` entry per event type and one for the event snapshot | A Rails payload and Go's reading of it drifting apart unnoticed |
| D2 | Where the contract lives | `personalization/contract/`, embedded in the Go binary with `go:embed`. Rails reads the same files in its specs | Go validating against a copy that differs from what Rails is tested against |
| D3 | Version field | `schema_version` in the envelope, one number for the whole contract. Current shape is version 1 | Go misreading a payload whose shape changed |
| D4 | When the version is set | Stored in a new `outbox_events.schema_version` column when the row is written; `DeliverEvent` copies it into the envelope | An old-shape row, still pending after a deploy, being sent with the new version number |
| D5 | Additions | Unknown fields are allowed everywhere (`additionalProperties` left open) and Go ignores them. Adding a field does not bump the version. A field Go starts to depend on stays optional in the schema and in Go until no row without it remains (as `revision` in MF-106) | Every additive change forcing a coordinated deploy; a new field breaking on old pending rows |
| D6 | What bumps the version | Removing or renaming a field, changing its type or meaning, making an optional field required | Go reading a changed field with the old meaning |
| D7 | Go at runtime, invalid payload | Validate against the embedded schema. Log one structured line (`event_type`, `schema_version`, `idempotency_key`, the schema errors) and still apply it, returning 204 | Stalling the outbox, and with it notifications and analytics, because of one bad payload |
| D8 | Go at runtime, unknown version or event type | Log and answer 422 `unsupported_contract` without applying. Rails keeps the row as a new outbox status, `deferred`: dispatched to notifications and analytics, not yet taken by Go, and never marked published. `bin/rails outbox:redeliver_deferred` sends deferred rows again; `Metrics.outbox_deferred_count` shows how many wait. A missing `schema_version` reads as 1 (Rails before this change) | Applying a payload Go cannot interpret; and, from review, silently losing it: a 204 would have let Rails mark the row published. Deferred is distinct from pending, so the poller moves on |
| D10 | Body size | Up to 10 MiB; above that 413 `payload_too_large` | A body cut off and reported as bad JSON. Like any delivery error, a 413 stops the poller on that row |
| D11 | Decoding | Go decodes the body once, loosely, and validates that value | A field of the wrong type returning 422 and stopping the poller; three parses per event |
| D12 | One list of event types | Read from each version's schema (`event_type` enum); `SupportedVersions` is the one list of accepted versions | A type added to the schema but not to a hand-written copy being refused |
| D9 | Rollout of a new version | Go first (accepts old and new), then Rails (writes new). Go drops the old version in a later deploy once `SELECT count(*) FROM outbox_events WHERE status = 'pending' AND schema_version = <old>` is 0 | Rails writing a version Go cannot read: Go would log and skip it, Rails would mark the row published, and the change would be lost from Go's read model |

## Design

### Contract files

```
personalization/contract/
  README.md                 what the contract is, D5/D6 rules, the upgrade steps (D9)
  embed.go                  package contract; //go:embed v1/*.json
  v1/
    events.schema.json      envelope + $defs per event type + $defs/eventSnapshot
    examples/
      EventPublished.json   one full envelope per event type
      ...
```

The envelope schema requires `schema_version` (const 1), `idempotency_key` (string), `event_type` (one of the seven) and `payload` (object). An `if`/`then` per event type points `payload` at its `$defs` entry.

`eventSnapshot` requires `id`, `title`, `location`, `starts_at` (date-time), `status` (`draft`, `published`, `cancelled`), `reserved_spots`, `capacity`, `topic_ids`, `visibility`, `organization_id`, `allowed_organization_ids`. `revision` is defined but optional (D5). `user_location` is a string or null.

### Rails

- Migration: `add_column :outbox_events, :schema_version, :integer, null: false, default: 1`.
- `Personalization::Contract::VERSION = 1`; `OutboxEvent` sets `schema_version` to it on create.
- `DeliverEvent` sends `{ schema_version, idempotency_key, event_type, payload }`.
- Test group gem: `json_schemer`.
- `spec/support/personalization_contract.rb`: an `after` hook on every example validates the envelope of each `OutboxEvent` row created during it against `personalization/contract/v1/events.schema.json`, and fails the example with the schema errors. Every spec that writes an outbox row checks the contract, with no extra code per spec.
- One contract spec that drives each producing service once, so every event type is checked even if no other spec writes it.

### Go

- A JSON Schema library (pure Go, draft 2020-12) compiles the embedded schema at startup. A schema that does not compile stops the service from starting.
- `ingest`: decode the envelope, validate. On errors, log `contract.invalid` with the details. Unknown `schema_version` or `event_type`: log `contract.unsupported` and return 204 without applying. Otherwise apply as today.
- No change to how fields are read: the zero-value fallbacks stay, because the payload is applied even when invalid.

### Tests

| # | Case | Expected | Kind |
|---|---|---|---|
| 1 | Every outbox row written in any spec | Valid against the schema, or the example fails | RSpec hook |
| 2 | Each of the seven event types | Envelope valid | RSpec |
| 3 | A payload missing `starts_at` | Hook reports the schema error | RSpec (the hook itself) |
| 4 | `DeliverEvent` envelope | Carries the row's `schema_version` | RSpec |
| 5 | Every example under `contract/v1/examples` | Valid against the schema; ingest returns 204 with no `contract.invalid` log; the stored event or topic follow has the example's values | Go test |
| 6 | An example with an extra unknown field | Valid; applied | Go test |
| 7 | A payload missing `starts_at` | 204, applied, `contract.invalid` logged | Go test |
| 8 | `schema_version: 2`, a string version, an unknown or missing `event_type` | 422 `unsupported_contract`, not applied, `contract.unsupported` logged | Go test |
| 8b | A field of the wrong type (`payload` an array, a numeric key, a string capacity) | 204, logged as invalid | Go test |
| 8c | Body over 10 MiB | 413 `payload_too_large` | Go test |
| 8d | No validator configured | Applied without checks, logged | Go test |
| 8e | Go answers `unsupported_contract` | Row `deferred`, its notification still sent, the next row published | RSpec |
| 8f | Go answers any other 422 | The poller raises, as before | RSpec |
| 8g | `outbox:redeliver_deferred` after Go learns the version | Readable rows published; the rest stay deferred | RSpec |
| 9 | No `schema_version` | Read as 1, applied | Go test |
| 10 | Schema compile | Fails at startup if broken | Go test |

## Out of scope

- Authenticating `POST /internal/events`.
- The outbox poller stopping on delivery errors.
- Version 2. This ticket defines version 1 and the steps for moving to 2.
